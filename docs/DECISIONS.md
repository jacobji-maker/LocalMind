# LocalMind 关键架构决策

日期：2026-10-21。状态：P0 实现决策；真实接入是否通过另见能力报告和验证记录。原有交接设计仍作为背景，协议冲突以 `PROTOCOL.md` 0.3 与最终实现校准记录为准。

| 编号 | 决定 | 原因及边界 | 重新评估条件 |
|---|---|---|---|
| ADR-001 | 原始事件、当前事项、请求快照分别保存 | 纠正不覆盖原始历史；摘要不能成为唯一依据。事项和来源都参与有效性检查 | 现成后端通过相同来源、修订、遗忘与迁移验收 |
| ADR-002 | Python 标准库 + SQLite，兼容本机 3.9.6 | 当前没有可直接使用的新版 Python/Node 项目环境；先交付可运行核心，不因 SDK 依赖阻塞确定性开发。代码保留升级到 3.11+ 的路径 | 项目独立 3.11+ 环境建立后，用同一回放验证兼容性再升级要求 |
| ADR-003 | 单进程、单写入者、短事务 | POSIX 进程锁防止第二运行时共享库，实例内 RLock + BEGIN IMMEDIATE 串行提交；模型推理和网络不持数据库锁。P0 不构建分布式 agent 平台 | 写入性能、隔离或并发需求有实测瓶颈；支持非 POSIX 平台时先验证等价锁 |
| ADR-004 | 规则基线先行，本地规划最多调用一次 | 本地模型提供候选建议，程序持有当前要求、来源、授权与预算。失败回退规则，保留可归因对照 | 隔离评测证明额外调用的增益超过延迟和资源代价 |
| ADR-005 | 自控消息入口，每用户回合重建应用历史 | 必要近期问答与当前状态由本地选择；“选第二个”仍能定位。相同回合内的工具往返不能被拆断 | 宿主提供可观测、可验证的等价历史控制能力 |
| ADR-006 | 云端首选受支持 Codex App Server 候选 | 优先核验现有登录路径；不读取或复制凭证，不把订阅等同 API key 额度。不静默切换付费 API | 受支持入口、认证及工具关闭实测通过；否则云端验收继续阻塞 |
| ADR-007 | P0 不执行自主电脑动作 | 记忆读取与结果接收足以验证上下文闭环。禁用 shell、非记忆 MCP/Apps 等必须由真实适配器能力保证，read-only 不足以证明 | 用户授权扩大产品范围，且每种新工具有能力与权限验收 |
| ADR-008 | 当前范围和生命周期由 LocalMind 持有 | 模型和外部后端不能自行扩权；暂停/删除/修订统一校验，旧结果不能反向写入当前状态 | 后端具备可独立证明等价语义的强约束接口 |
| ADR-009 | 结构 Schema + 语义校验一起使用 | schema 合法的 inferred/candidate/失效硬约束仍需拒绝；所有来源必须在当前授权内可重新核对 | 不取消语义校验，只有实现方式可替换 |
| ADR-010 | 真实 UTF-8 字节预算，token 明确标估算 | 本机没有锁定的供应商 tokenizer；可确定限制受控应用消息大小，不能冒充完整 prompt 窗口保证 | 锁定 tokenizer 和模型窗口，验证宿主隐式开销后增加精确计数 |
| ADR-011 | 实际发送、回放、文档能力分别记录 | 捕获 packet 不等于接通；回答看似正确不证明旧历史退出或工具关闭；mock 不参与真实集成通过判定 | 保持此区分 |
| ADR-012 | 保留 0.2 交接资料，不自动升级旧包 | 旧 schema 不含完整授权、来源及生命周期语义；版本号替换不能补回缺失事实 | 正式导入器完成墓碑优先、来源复核与事项重建验收 |

## 接入决策门槛

0.4 插件增量：MCP 提供固定项目范围的只读数据通道，不把模型参数变成用户确认；写入走受信 CLI。服务逐次打开并释放 Store，使用户的暂停、纠正与遗忘在后续读取中生效；不保留跨请求结果缓存。新历史召回使用有界候选和完整数据扫描，未达到大规模检索性能验收。`remember` 的 capture-only 终态见 PROTOCOL.md。

并发策略补充：同步纠正先提交，再等待串行前台推理位置；待发普通请求等待已提交纠正。过时的回答不更新 last_result，也不向调用者返回原 packet/messages。真实远端线程 ID 与 request_id 绑定保存，不能被重绑。

唯一候选云端路线是自控命令行到受支持 Codex App Server；只有客户端可启动、认证类别可观测、干净应用历史可验证、实际消息可捕获，以及自主工具被真实关闭后才能标记通过。任何一项未知都不能用“已经有 Codex 应用”代替。本地 Ollama 和确定性 Replay 各自可以开发运行，但不能替代真实云端验收。

工具暴露需分别检查 shell、web search、MCP、Apps、动态工具及直接执行 RPC。空动态工具列表、read-only 沙箱或提示“不要调用工具”不是完整关闭证据。记忆实现不代理任意宿主 RPC。

只读 MCP 数据入口已实现，0.5 新增单次预算化 recall；原生 Hooks、自动捕获与当前宿主实际加载仍待验收。Hooks 是受支持事件中的 additive 补充，MCP 由宿主按需调用；两者不保证删除宿主既有历史。当前项目不修改全局 Hook 配置或替换任意 ChatGPT 网页聊天入口。

0.5 采用共享模型投影与严格编号解释，内部审计不直接外发。同一已见开发集合真实复测为MCP11/11、核心10/11、完整历史11/11；MCP输入仍为完整历史1.475倍。该结果支持当前改动在已见短历史场景中的改善，不能作为语义召回、未见场景、长历史或原生宿主接入的通过证据。详细架构与边界见 ARCHITECTURE_0.5.md，原始数据见 contrast-report-0.5.json。

## 实现取舍与限制

M5、16GB 内存是当前开发机资源事实；模型名称、推理位置、延迟和效果需要分别实测。已安装模型不证明已加载，本机服务也不自动证明离线推理。不会自动下载大型模型来满足一次测试。

派生摘要、缓存或第三方记忆引擎仅返回候选。P0 不安装九套上游系统，不引入图数据库、微调、多设备同步或后台持续反思。机制参考及许可证继续使用 `OPEN_SOURCE_REVIEW.md`，未锁定源码并通过测试的组件不写成已采用依赖。

明确纠正由已定位事项的同步接口保证；任意中文自然语言的完整理解不是程序可以无条件承诺的能力。未知目标保留原话、暴露 unknown；不可为了让演示看起来顺畅而自动猜定用户要求。

删除先实现本地逻辑不可读和依赖失效。SQLite 旧页、外部备份、云端留存的物理删除没有默认承诺；以后开放恢复功能前，必须先实现当前墓碑优先合并。

## 必须保留的验证证据

- 原话与实际适配器消息逐字一致，近期问答身份及选项顺序正确。
- 纠正后旧结论、旧摘要和旧在途结果不能回写；项目/全局版本变化也会使待发包过时。
- inferred/candidate、无真实用户来源及越界来源的硬约束被拒绝。
- 暂停与删除后的原文、审计副本、展开及晚到结果受统一屏障。
- 必要条件与预算冲突时明确失败；不存在静默截断许可前提。
- 未知远端结果在重启后不自动重发；真实云端与合成 Replay 结果分别标注。

这些是验收要求，不是本文件声称已经运行通过的测试结果。

## 0.5 架构决定

ADR-013：完整审计留在本地，projection.py 外发一次来源表、有效事项和完整原文。核心消息与 MCP recall 共享投影；recall 只保证补充预算，宿主须预留自身开销。

ADR-014：严格编号选择只产生有用户确认和固定原提议双来源的解释，原字面状态不改写。否定、条件、缺号及不支持格式不猜测，也不把解释当作独立权限。

ADR-015：当前账户与仓库分别核验；按本轮明确授权发布到 jacobji-maker/LocalMind 的公开仓库，排除数据库、凭证及机器配置。其他账号和项目的可见性不变。
