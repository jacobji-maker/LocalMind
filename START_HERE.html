一套本地核心，两种接入方式

程序管理范围、版本和提交；小模型提出建议；云端完成复杂推理。原始记录保留，摘要可以重建，云端模型可以更换。

关键机制

问题架构决定
“这个”“之前那套”指什么当前项目与任务优先，结合近期原文和候选记忆。多个解释影响结果时简短消歧。
记错了、要求变了已确认修订立即更新；未决冲突暂停旧硬约束，保留本轮原话并必要时消歧。
越聊越长保留原始请求、硬约束和关键证据，去重并缩减可选历史；自控入口管理检查点与有限会话。
小模型压错或超时原文始终可回查，程序校验证据；失败降级为规则检索，不隐式转收费云端。
项目串线、遗忘后复活范围默认隔离；删除清单覆盖派生摘要、索引与缓存。旧云端线程的历史需另行处理。
主动意味着在合适的事件点运行。 每次发送、纠正、收到工作结果时更新；空闲时有界整理。默认无需你逐条挑选记忆。暂停后不采集、不注入、不回写旧在途结果；恢复默认不补采暂停内容。

完整闭环先用可控入口验收

入口能力与阶段
LocalMind 命令行 + Codex SDK / App ServerP0 主路径。每回合使用干净远端线程，明确提供有限历史、状态与原始请求。
本地 Codex HooksM0 提前核验，P1 保留原生使用体验。适合自动补充；已有历史仍由宿主管理。
MCP 记忆工具用于按需检索与原文回查；单独暴露工具不保证每轮都会调用。

官方接口能力已经查证，本机集成仍需验证。不能把本地 Hooks 的能力套用到云端编排或任意现有 ChatGPT 网页聊天。

技术起点：Python + SQLite + 一个本地模型后端。具体模型待中文效果、可用硬件和延迟实测选择。优先评估已有 Codex 登录支持的路径；通用 API 费用单独处理。

按五个里程碑推进

  1. M0 接入验证：真实入口、当前客户端、模型后端和能力报告。
  2. M1 可纠正记忆：原始事件、分区、修订、暂停、遗忘与恢复。
  3. M2 规则上下文：中文检索、预算、来源与实际请求捕获。
  4. M3 本地模型：意图与选择增强、候选压缩、降级与后台整理。
  5. M4 长历史验收：压缩检查点与公平对照，证明关键要求仍能影响回答。

首版把自主操作电脑放在后续。核心验收同时检查：发出了什么、记忆变成什么、最终做了什么。

开发包含原有 30 条与新增 12 条，共 42 条合成回放种子。正式验收另设未见集合，比较无主动编排、规则检索、本地小模型编排三组；可选再替换单一开源后端对照。

开源经验已经合并进设计

优先借鉴 OpenViking 的分层上下文、claude-mem 的按需展开、Hindsight 的事实与归纳分离。当前状态、用户纠正和外发预算由 LocalMind 持有。

补强机制实际作用
先纠正，再召回已确认的新要求当轮生效，后台旧结果不能覆盖。
检查信息缺口没有证据就保留未知，不生成看似合理的记忆。
来源失效传播原始要求修订或删除时，相关摘要立即停止使用。
注入回声过滤自己的旧补充和复述不算新的独立证据。

开发回放共 42 条，均为合成设计场景，尚未运行产品评测。现成框架只选一个做对照，不同时叠加多套运行时。
